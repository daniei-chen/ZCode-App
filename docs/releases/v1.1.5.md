# v1.1.5 — 启动盖板与主题双向同步（真机 v1.1.4 反馈）

> 版本：`1.1.5+16`。基于 v1.1.4 真机反馈（两台设备诊断包均 bridge=ok、
> 返回链零错误），处理三项体验问题。

## 变更

**1. 首次加载：应用图标盖板盖住"正在配对工作区 / 加载工作区中"**

远控页新增原生品牌启动盖板（应用图标 + 加载指示，不透明背景）。文档加载
完成 ≠ 工作区可用——盖板持有到探针确认真实内容（任务列表行或输入区出现，
300ms 轮询）或 12 秒超时兜底揭开。任何一次全新文档加载（首启/静默重载/
渲染进程重建）都会重新挂盖板，用户不再看到 web 端的启动过渡过程。

**2. 切换会话/慢配对：握手卡"冷处理"词表更新 + 观察窗延长**

既有握手卡隐藏器（display:none，命中即断开）的词表是旧文案
（正在加载工作区/同步桌面端工作区/等待桌面端配对）——官方页 3.12.x 新
文案是"正在配对工作区 / 加载工作区中"，不在词表里，所以卡片原样露出。
现按词根匹配（加载工作区/配对工作区/同步桌面端工作区/等待桌面端配对
+ 英文 pairing workspace），观察窗 5s → 30s（慢设备下卡片可能更晚出现，
仍保持有界）。模拟器实测：SPA 切换会话不产生页面重载
（`performance.timeOrigin` 不变），叠加盖板与词表后冷启动过程全程被盖。

**3. 主题双向同步（去掉强制锁定）**

旧机制：应用注入后用 MutationObserver **强制回写**，页面手动切主题只在
"点击后 2.2s 手势窗"内被容忍——官方页主题菜单是两步异步操作，窗口一过
选择就被改回去（真机反馈"被强制锁定"），且上报需要窗口活跃，双向都失灵。
新机制为确定性比较：应用注入时把归一化主题写入 `__zcodeControlAppliedTheme`
基准；观察者发现页面生效主题 ≠ 基准时上报 `zrTheme`（120ms 去抖），
应用更新后重新注入同一决定（此时比较相等，天然收敛）。双向都即时生效，
任何时刻页面都不会被改回去。

**4. 平板：设置返回 → 对话/列表同屏页 → 再返回 → 设备页**

按用户 2026-09-15 口径双端区分（v1.1.4 的"设置返回=设备列表页"仅保留
在手机）：

| 场景 | 按返回后 |
| --- | --- |
| 设置/诊断/扫码（**手机**） | 设备列表页（普通弹栈，一次到位） |
| 设置页（**平板**） | 对话 + 列表同屏页（外壳揭示远控页） |
| 对话页（平板，同屏） | 设备列表页（一次返回到位，页内脚本不跑） |
| 对话页 → 对话列表（手机） | 页内返回（`WV112/clicked`） |
| 对话列表（手机） | 设备列表页（稳定态立即返回） |
| 设备列表页 | 退出应用 |

## 验证

- `flutter analyze` 零问题；back_navigation 测试 15/15（新增平板/手机
  设置返回差异 2 例）；全套测试以 CI 为准（Windows 本地仅 4 例已知引擎
  着色器限制失败，与改动无关）。
- 模拟器实测：冷启动全程只见品牌盖板（加载工作区卡被词表隐藏 + 盖板
  覆盖）；SPA 切换会话无重载无加载页；平板 800×1280dp 设置返回回同屏页、
  再返回回设备页；手机 320×640 设置返回停设备列表页。
