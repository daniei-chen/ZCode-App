# 合规边界（项目约束）

> 本项目是**面向自有设备的移动端伴侣 App**，不是通用远控工具。
> 本文是硬约束，实现与后续迭代都必须遵守。

## 一、我们做的事

ZCode Control 通过 ZCode 桌面端**官方提供的"移动端远程控制"功能**接入：

- 凭证来自**用户自己的桌面端**出示的二维码（`sid` / `hash` / `mid`），
  与官方手机页面用的是同一套授权
- 连接、握手、订阅都**按官方协议原样实现**，不伪造、不改写、不放大权限
- 读取的是**用户自己账号下、自己机器上**的工作区与会话数据
- 目的是**互操作性**：让用户在自己的手机上，用自己的账号，看自己的数据

这与"用手机浏览器打开官方远控页"在授权范围上完全一致，
差别只是把渲染层从 WebView 换成了原生 UI。

## 二、明确的红线

以下行为**不做**，也不接受为"顺手加个功能"的理由：

1. **不绕过鉴权**。不破解、不猜测他人的 `sid` / `hash`；不实现凭证枚举、
   批量探测、会话劫持。relay 单配对限制（`sessionConflict` / `kicked`）
   是官方设计，不去规避。
2. **不碰账户与计费**。协议里存在 `/api/v1/zcode-plan*`、`billing`、
   `coding-plan-subscription` 等端点 —— **一律不调用**。
   不做额度绕过、不做套餐相关读写。
3. **不做提权与横向移动**。不做"控制他人设备"、不做多目标批量接管。
4. **不上传用户数据**。会话内容、工作区路径、凭证只在本机内存与本地存储流转，
   不经由任何第三方服务。
5. **不把协议细节做成通用工具**。协议结论记录在仓库文档里是为了说明实现依据；
   不提供针对**他人**会话的现成攻击脚本或凭证生成器。

## 三、写操作的额外要求

远程控制本身包含写操作（批准、发指令），这些是**用户对自己机器**的合法操作，
但风险更高，因此：

- **默认只读**。订阅、拉取正文、读取状态属于只读，可直接实现。
- **写操作逐个确认**。任何会改变桌面端状态的动作（批准待办、发送指令、
  编辑会话）必须在实现前单独评估，并在 UI 上要求用户明确触发，
  不提供"自动批准"这类静默路径。
- **要有可见反馈**。写操作必须让用户看到发起了什么、结果如何。

## 四、凭证卫生

- 二维码链接 = **控制该台桌面的能力凭证**，等同密码
- 不写入版本库、不写入日志文件、不贴进公开 issue
- 本地调试用的凭证存放于 `tools/`（已被 `.gitignore` 排除）
- 建议：调试结束或链接外泄后，在桌面端**刷新二维码**使其失效

## 五、已知的不确定性

- 这是**未公开的内部接口**，官方未承诺兼容；协议可能随版本变化
- 官方客户端类型枚举里包含 `mobileApp`，说明原生形态是被预期的；
  但服务端对它的处理分支可能与 `web` 不同（实测见
  [RELAY-PROTOCOL-VERIFIED.md](RELAY-PROTOCOL-VERIFIED.md) 第八节）
- 若官方明确表示不接受第三方客户端接入，应停止相关实现
