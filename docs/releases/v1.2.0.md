# v1.2.0 — 常驻监控前台服务 + 完成/审批/报错通知全弹

> 版本：`1.2.0+32`。按用户要求对齐 DeepSeek-Harness-APP 的常驻通知模型：
> 通知栏常驻保活，任务完成、审批请求、报错都要弹系统通知。

## 变更

**1. 常驻监控前台服务（通知栏常驻）**

新增 `MonitorKeepAliveService`（`dataSync` 前台服务）：通知栏出现一条
静默的「ZCode 远程监控运行中」常驻通知，作用是**把进程保活**——WebView
的 `wss://zcode.z.ai/ws` 事件流在后台与锁屏期间不再被系统杀掉，任务通知
从此可持续到达。

* `START_STICKY`：系统杀死后自动重建；
* 划掉最近任务**不算**停止监控；
* 服务是纯保活（无轮询/无网络/无业务逻辑，K1 安全不变量改写后锁定该
  边界）——事件解析与通知决策全部仍在 Dart 侧；
* 应用每次启动自动拉起，无需手动开启。

v1.0.0 曾有过自带轮询的 KeepAliveService（耗电、观测面大），v1.0.1 移除
并用 K1 不变量锁定"不得复活"。本次以纯保活形态回归，K1 同步改写为新边界。

**2. 通知门禁对齐 DSH 规则**

旧规则：App 在前台时一律不弹系统通知。新规则：

* 后台/锁屏：完成、审批、报错**一律弹**；
* 前台：也弹——只有"正盯着这台设备的这个会话"才静默（此时应用内浮窗
  已经在眼前，不重复打扰）；
* 设备级失败信封（`app-error`，无会话归属）：前台也照常弹。

**3. 小米/HyperOS 用户必读**

常驻通知保活要生效，系统侧需要放行一次（每台手机只需一次）：

* 设置 → 应用 → ZCode → 省电策略 → **无限制**；
* 设置 → 应用管理 → ZCode → **自启动** 允许（App 内 设置 →
  「电池优化/厂商后台限制」入口可直达）；
* 若常驻通知被手动划掉，重新打开 App 即会恢复。

## 升级

versionCode 32 > 31，签名同钥匙（07091ffd…），覆盖安装免卸载；升级后
首次启动即出现常驻通知。

## 验证

* `flutter analyze` 零问题；全套测试无新增失败（4 个本机环境性失败与
  干净 main 一致；K1 不变量改写为锁定纯保活边界，正反用例齐全）。
