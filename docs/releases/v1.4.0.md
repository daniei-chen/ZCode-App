# v1.4.0 — 通知栏直接办事 + 首页官方风格 + 自诊断

> 版本：`1.4.0+37`。三件事：审批/回复按钮落地、首页换成 ZCode 官方
> "选择电脑"风格、通知链路可自诊断。

## 1. 通知栏动作按钮（核心）

* **审批通知挂「允许 / 拒绝」**：拿到选项 id 时直接在通知上放行/拒绝
  （resolveInteraction，answer={optionId}——全部字段形状逆向自官方
  3.16.3 页面代码并交叉验证）；
* **完成/提问通知挂「回复」**：通知栏输入框直接发下一条指令
  （sendText，RemoteInput 直达）；
* 按钮经通知插件的**后台隔离体**分发——不依赖两个引擎谁活着；
* 命令走独立的 agent 通道（第二条 WS：开桥 → hello → initialize →
  订阅会话索引），与监控连接互不影响：agent 层任何故障最多退化为
  "没有按钮"，监控通知不受牵连；
* 二进制 RPC 编解码按协议文档逐字节实现，CRC/帧/base64 全部有金向量
  单测锁死（实现期一个 CRC 有符号溢出 bug 被 Python 交叉验证当场抓获）。

**诚实说明**：写路径的订阅推送形状无法在 PC 上活体验证（本机没有有效
的远控页令牌）——事件解析因此是防御性的（认字段不认信封，形状不符就
丢弃不崩）。如果按钮没出现/点了没反应，导出诊断包反馈，下一版修。

## 2. 首页改版（ZCode 官方"选择电脑"风格）

黑色 Z 徽章 + 大标题「选择电脑」+ 刷新；账号行显示登录身份；设备卡
换成 56px 大图标 + 左下角在线状态点 + 状态副标题（在线/连接中/异常 ·
添加日期）；分组标签显示在线计数。暗色模式同步适配。

## 3. 通知自诊断（回答"为什么没通知"）

* 诊断页新增「远程监控」分区：每台设备显示已连接 / 等待桌面端配对 /
  **未捕获登录令牌（打开一次远控页即可）** / 连接中 / 断开重连中——
  状态由监控引擎经共享存储跨隔离体上报（此前监控引擎的日志对诊断包
  完全不可见，这是盲区）；
* 监控引擎启动加固：开机自启先于界面时引擎创建失败的竞态已修
  （ensureInitialization + 失败重试），此前该场景监控会静默消失。

## 升级提示

装好后仍要：打开一次远控页（捕获登录令牌）→ MIUI 开自启动 + 省电
无限制。之后看 诊断 → 远程监控：显示"已连接"即链路健康。
