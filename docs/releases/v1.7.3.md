# v1.7.3 — 修复打开闪退（前台服务权限缺失）

> 版本：`1.7.3+47`。**紧急修复 v1.7.2 的启动闪退**（用户实测："打开闪退"）。

## 根因

v1.7.2 把常驻前台服务的类型从 `dataSync` 改成 `specialUse`（为了绕开
Android 15 对 dataSync 的 6 小时配额），但**漏了配套权限**
`FOREGROUND_SERVICE_SPECIAL_USE`。

Android 14+ 上前台服务类型与权限必须成对：`startForeground(id, notif,
TYPE_SPECIAL_USE)` 在缺少该权限时直接抛 `SecurityException`。而本服务在
`MainActivity.onCreate` 之后立刻被拉起——异常发生在主线程启动路径上，
用户看到的就是**打开 App 即闪退**。

## 修复

1. **补上 `FOREGROUND_SERVICE_SPECIAL_USE` 权限**（`dataSync` 权限保留，
   API 29–33 的降级分支仍在用）。
2. **`startForeground` 改为绝不上抛**：类型被拒 → 退回 `dataSync` →
   再失败 → 退回无类型 `startForeground` → 最后放弃前台化（服务继续跑，
   只是后台存活概率降低）。任何一步失败只记日志，不带崩进程。
3. **`onCreate` 两步（前台化 + 头无引擎）各自 try/catch**：这个服务在启动
   路径上，任何异常都会被用户感知成"闪退"，所以整条链路 fail-closed。

## 实机验证（MuMu，Android 16 / API 36）

- 全新安装 → 启动：进程存活、界面正常渲染、无崩溃记录；
- `dumpsys` 确认服务前台化成功：`isForeground=true`、
  `types=0x40000000`（`FOREGROUND_SERVICE_TYPE_SPECIAL_USE`）；
- 头无引擎启动成功（`headless engine started`）；
- 切后台（Home）→ 回前台：进程全程同一 pid，无闪退，服务始终在前台。

## 升级注意

v1.7.2 会导致启动闪退，**请直接安装 v1.7.3**（versionCode 47）。
已装 v1.7.2 的设备卸载重装即可（数据在应用私有目录，卸载会清登录态，
需要重新登录一次）。
