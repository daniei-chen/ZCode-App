# v1.8.1 — 外置通道可完全自定义 + 检查更新失败可诊断

> 版本：`1.8.1+49`。用户提出两个问题：①别人不用我的链路、应该可配置；
> ②"检查更新失败了"。本版把前者做实，并给后者补上可诊断性。

## 一、外置通道协议可完全自定义

v1.8.0 里服务器地址与令牌本来就是自由填的，但**端点路径和鉴权头是写死的**
（`/zpush/poll`、`/zpush/ack`、`X-ZP-Token`），别人自建服务时必须照抄。
现在三处全部可配（设置 → 外置通知通道 → 高级：端点与鉴权）：

| 配置项 | 默认（本项目服务） | 可改为 |
|---|---|---|
| 轮询端点 | `/zpush/poll` | 任意相对路径或完整 URL |
| 确认端点 | `/zpush/ack` | 同上 |
| 上报端点 | `/zpush/publish` | 同上（仅用于桌面端提示） |
| 鉴权方式 | 请求头 `X-ZP-Token` | `Authorization: Bearer` / `?token=` 查询参数 |
| 鉴权头名 | `X-ZP-Token` | 任意头名 |

留空即用默认值——继续用本项目服务的人什么都不用改。端点支持填完整 URL，
因此轮询和确认甚至可以指向两个不同的服务。

**协议契约**（自建服务只需满足这些，不要求用我们的实现）：

```
GET  <pollUrl>?after=<id>
     ← {"ok":true,"messages":[{"id":123,"kind":"permission",
        "title":"…","body":"…","sessionId":"…","device":"…","ts":1700000000}]}

POST <ackUrl>   {"ids":[123]}
     ← {"ok":true,"acked":1}

鉴权：按上面选的方式带令牌
语义：after 之后、未投递；ack 之后不再返回
```

## 二、检查更新失败：先查清，再补诊断

真实链路联调结果（`test/update_integration_test.dart`，直连真实网络）：

- ✅ 镜像地址通过出站白名单
- ✅ `checkForUpdate` 返回可用结果（不是 failed）
- ✅ 以最新版为当前版本时正确判 `upToDate`
- 全程约 1 秒

镜像服务端也实测正常：`https://zhihui.kaogong.art/zcode-release-latest`
返回 200、1.17 秒、`tag_name: v1.8.0`、资产名 `ZCode-v1.8.0.apk` 正确。

**结论：链路本身没有故障。** 之前"检查更新失败"最可能是当前安装版本较旧
（v1.7.x 及更早）在网络抖动时三条链路同时超时，而旧版只显示一句
"检查更新失败，请稍后重试"，无法判断原因。

**v1.8.1 的改进**：`UpdateCheckResult` 增加 `failureReason`，失败时
按原因给出人话提示，并写 `UP600` 结构化日志：

| 原因 | 提示 |
|---|---|
| `version_unavailable` | 检查更新失败（读不到当前安装版本） |
| `api_timeout` | 检查更新失败（网络超时） |
| `api_error` / `api_and_mirror_failed` | 检查更新失败（直连与镜像均不可用） |

以后再失败，从提示就能判断是网络问题还是配置问题。
