# ADR-005 无系统锁屏凭据机型的擦除失败出口

- 状态：**提议，待产品决策**（2026-09-16）· 级别 P2
- 关联：R-02/R-03/R-04（门禁恢复二选一）、R-17（擦除失败语义）、b5 评审 H-2（通知撤销重试）

## 背景

安全设置读取失败时，锁屏提供二选一：**A** 系统凭据验证一次 → 关开关保数据；**B** 擦除全部受保护数据 → 免验证放行。没有系统锁屏凭据的机型走不了 A；若 B 的擦除事务失败（存储不可写、插件通道故障），用户会被锁死。b5 已做：通知撤销短退避重试 + 失败文案给出"系统设置清除应用数据"的等效出路。未决：是否再提供"显式知情确认"出口（承认数据可能残留、仍放行）。

## 候选

| 方案 | 做法 | 收益 | 代价 / 风险 |
| --- | --- | --- | --- |
| A 现状 | 擦除失败 → 如实报错 + 指引系统设置清数据 | fail-closed 不松动 | 用户需离开应用去系统设置操作；极端机型可能反复失败 |
| B 显式知情确认出口 | 失败 N 次后出现"我了解数据可能残留，仍要进入"二次确认 | 不锁死 | 削弱 fail-closed：受保护数据（凭证）可能在放行后仍在磁盘且门禁已关 |
| C 分级失败 | 存储/凭证擦除失败 → 硬失败（不放行）；仅通知撤销/站点数据等非凭证项失败 → 软失败放行并留痕 | 精确区分"凭证还在"与"附属残留" | 需梳理擦除事务每一步的失败等级并测试 |

## 推荐

**C**，并按数据敏感度定级（`lib/services/wipe_result.dart` 的 7 个 `WipeStep`）：

- **硬失败（不放行）**：`providers`（内存态凭证）、`secureStorage`（设备凭证与索引）、`lastDevice`（指向凭证的指针）、`siteData` 与 `cookies`（官方站点会话态，凭证相邻）；
- **软失败（放行 + 留痕 + 诊断页提示 + 下次启动重试）**：`notifications`（payload 只含设备/会话 id，且插件本无查询 API，成功也只是"已提交"）、`cache`（HTTP 缓存，无凭证）。

B 只在有真实用户被锁死的反馈且 C 仍不能解决时考虑。

**现状核对（2026-09-16）**：`wipe_result.dart` 明确"全部为必需项，任一项失败即不放行"，`allRequiredSucceeded = steps.every(ok)`；b5 为 `notifications` 加了一次 200 ms 退避重试（`notifier.dart cancelAll`），但该步**仍是必需项**。因此 C 是一次真实的语义变更，需要用户确认定级口径。

## 需用户决定的点

- 是否接受 C 的分级口径（附属类残留可放行）；
- 是否需要 B 作为最后出口。

## 验证

- C：`protected_wipe_test` 增加"凭证擦除失败 → 不放行"与"仅站点数据失败 → 放行且留痕"两条；`biometric_gate_test` 生产拓扑回归。

用户拍板后；或收到锁死反馈时。
