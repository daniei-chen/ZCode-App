# v1.3.0 — 第二条事件源 + 连接状态可见 + 通知历史：24 小时通知的三块拼图

> 版本：`1.3.0+35`。目标：把 v1.2.x 打好的通知地基补成"WebView 不在也
> 有来源、断连有感知、错过能回看"的完整链路。

## 变更

**1. 原生监控通道（核心）——绕过 WebView 直连中继的第二条事件源**

新增 `wss://zcode.z.ai/ws` 原生直连（JSON 层，只读）：对官方 3.16.3 页面
bundle 逆向确认了 V2 握手——`auth_init{device_sid}` → `auth_ack`，已无
V1 的 challenge/HMAC，sid 即凭证，无额外门槛。每台设备常驻一条监控连接
（握手 → 5s 心跳 → 15s 任务快照轮询），复用与 WebView 完全相同的
提取器/差分器/幂等闸门/通知门禁：

* **WebView 加载失败、后台被冻结、页面崩溃时，完成/失败事件仍有来源**；
* 快照与已有会话状态做**字段级合并**，绝不把 WebView 侧的"等待审批"
  计数覆盖清零（否则会误撤审批通知）；
* 通知 id 与 WebView 路径一致（stableId），极端重复只替换不堆叠；
* 本版仍为只读通道：审批/回复的**写**路径需要二进制 RPC 层
  （resolveInteraction/sendText），规划 v1.4。

**2. 连接状态可见（仿 DeepSeek-Harness 的"连接状态"类别）**

WebView relay socket 与原生监控双源聚合，任何一方有生命迹象即在线；
双源沉寂 45 秒（吸收重连抖动）才算断连：

* 断连 → IMPORTANCE_LOW 静默通知「连接已断开，恢复后自动重连并提醒」；
* 恢复 → 同 id 通知替换为「连接已恢复」，不堆叠；
* 常驻通知文案三态：远程 / 已连接到 `<设备名>` / 连接已断开，恢复后自动继续。

**3. 通知历史**

送达的系统通知本地留底（最多 200 条），设置 → 通知 → 通知历史可回看；
点击条目与点通知一致，深链直达对应会话。只存展示文本与深链载荷，
无凭证、无会话正文之外的敏感面。

**4. 通知栏"打开会话"动作按钮**

每条告警通知带「打开会话」按钮（行为同点按通知体）。审批/回复按钮
等原生写路径落地后一并加入。

**5. 开机自启 + 厂商省电引导补全**

* `BOOT_COMPLETED` 接收器：重启手机后自动拉起常驻监控，不再断档；
* 厂商检测真实化（此前恒为 false，设置页的红色警示从未生效）：小米/
  红米/华为/荣耀/OPPO/一加/vivo/iQOO/魅族/三星 且未进电池白名单时，
  保活入口转红并直跳对应 ROM 的自启动/功耗管理页（逐个回退到应用详情页）。

**6. 设备中心显示登录账号**

V2 账号流里所有设备同属一个已登录账号——账号探针从受信任页面读登录
令牌解出展示名，在设备中心头部显示「登录账号：<名>」（只在本机展示，
不进日志与诊断包）。账号中心化的第一片。

**7. 顺手修复**

* 「发送测试通知」仍指向已删除的 v6 渠道（v1.2.2 渠道升级遗漏），
  测试按钮在部分机器上无声无息——修正到 v7 渠道族。

## 已知边界

* 原生监控对**审批/输入请求**不独立告警（快照任务不含交互计数，
  那两条仍依赖 WebView 事件流）；完成/失败 + 连接状态已双源覆盖。
* 通知栏直接审批/直接回复需要二进制 RPC 写路径（v1.4）。
* MIUI 等厂商 ROM 的自启动权限仍需在引导页放行一次。
