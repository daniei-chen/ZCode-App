# ADR-003 发布签名密钥接触面事件的处置

- 状态：**提议，待用户拍板**（2026-09-16）· 级别 P0（治理）
- 关联：`docs/PROJECT_AUDIT.md` A-01；台账"密钥处置决策（b3 明文包 + 终端误输出两事件）"

## 背景

两次接触面事件：① b3 审计包曾以明文包含签名密钥目录（后续包已改为"含密钥/不含密钥"双变体，含密钥版只交可信审计方）；② 一次终端误输出。目前无证据表明密钥流出到审计方与本机之外，但**无证据 ≠ 无风险**。

约束：Android 覆盖安装要求同签名。分发渠道为 GitHub Releases（非 Play），无 Play 签名托管。`minSdk 24`；APK Signature Scheme v3 密钥轮换（lineage）需 API 28+ 才能被系统接受，API 24–27 设备无法跟随轮换。

## 候选

| 方案 | 做法 | 收益 | 代价 / 风险 |
| --- | --- | --- | --- |
| A 保留密钥 + 加固流程 | 不轮换；密钥只存离线备份与 CI Secrets；`verify-keystore-backup.sh` 定期核验；审计包永久禁带密钥（不含密钥版为唯一对外形态）；记录事件与评估 | 零用户影响 | 若密钥已在不可见处流出，恶意 APK 可冒充升级（用户需先安装恶意包，且更新器有 SHA256 + 出站白名单双门，风险受限） |
| B v3 密钥轮换（lineage） | 生成新密钥，用 `apksigner rotate` 建立 lineage，新包同时带旧→新证明 | API 28+ 设备无感升级 | API 24–27 设备需卸载重装（数据丢失=需重新导入设备）；工具链与 CI 签名步骤改造；发布脚本 manifest 需记录 lineage |
| C 全新密钥 + 强制重装 | 新密钥，公告所有用户卸载重装 | 彻底切断 | 全部用户丢数据（凭证需重扫）；更新器"检查更新"会判为无法覆盖，需专门提示 |

## 推荐

**A 立即执行 + B 作为预备**：现在落实 A 的流程加固（成本最低、无用户影响），同时离线生成 B 所需的新密钥与 lineage 但**不发布**——一旦出现流出证据即可切换 B，将 API 24–27 用户的重装成本作为已知代价公告。C 只在确认大范围泄漏时启用。

## 需用户决定的点

1. 是否接受"保留现密钥"的残余风险（对两次事件的暴露面判断）；
2. 是否现在就生成 B 的预备密钥与 lineage（涉及密钥保管地点、口令策略——**只能由用户在本机/离线完成，AI 不接触密钥材料**）；
3. 复审周期（建议：每次出包前 + 任何新的接触面事件后）。

## 验证

- A：`scripts/verify-keystore-backup.sh` 通过；审计包出包脚本默认不含密钥且有 security-auditor 扫描记录；`.gitignore` 覆盖 `*.jks/*.keystore/key.properties`（已核验）。
- B（若启用）：`apksigner verify --print-certs-lineage` 显示 lineage；API 28+ 模拟器覆盖升级成功；API 24 模拟器验证"需重装"提示路径。

## 回退

- A 无回退需求；B 一旦发布 lineage 不可撤回（只能继续向前轮换）。

用户拍板后立即记录到 `docs/DECISIONS.md`；之后每次出包前复审。
