# v1.6.3 — MuMu 实测攻坚：通知链三大根因修复 + 协议补全

> 版本：`1.6.3+43`。本轮在用户的 MuMu 模拟器上全程 adb 驱动实测，
> 连续挖出并修复三个"收不到通知"的根因，V2 协议全链 PC+MuMu 双实测打通。

## 三大根因（全部实测实锤）

**1. 后台原生监控从未启动过（v1.3.1 起）**
`monitor_main.dart` 没有被任何文件 import——AOT 只编译 main.dart 的
传递导入图，头无引擎的 DartEntrypoint 在 release 快照里**不存在**
（红字：Could not resolve main entrypoint function），失败被静默吞。
且 DartEntrypoint 的入口名只在**快照根库（main.dart）**查找，定义在
其他文件无效——修复：入口包装函数移入 main.dart + 引擎启停日志
（logcat 可查，不再全静默）。

**2. WS 白名单认错了端点代际**
V2 页面的 relay WebSocket 是 **`/api/v1/remote/ws2`**（WV114 路径留痕
实测），旧白名单只认 V1 的 `/ws`——页面事件流整体被忽略
（诊断包 wsMessages 恒 0、wsIgnored=2 的真身）。白名单覆盖两代端点。

**3. V2 令牌链缺失（协议补全）**
ws2 不接受登录 JWT（401），要先用 JWT 换**60 秒短效 relay 令牌**：
`POST /api/v1/remote/token {role:"terminal"}` → `{token, expires_in:60}`。
请求/响应 schema 逆向自官方校验模块，**PC 全链实测**：交换 → ws2 →
auth_ack matched → 任务快照（设备/工作区全量返回）。监控与命令通道
均已接入（每次建连前现换，过期自动重换）。

## 4. 账号为中心的结构修正（用户截图反馈）

* **账号设备区短路 bug**：账号设备卡片挂在"手动设备非空"分支下——
  全新装机手动为 0 时**登录成功也永远不显示设备**。已独立渲染；
* **目录设备自动落库**：登录后目录里的设备自动进 app（sid 去重，
  账号侧增删自动跟随），首页直接显示 + 在线计数用目录权威字段；
* 在线统计移到账号行右侧（官方排版）；登录页 URL 带设备参数
  （裸地址官方页直接进失败卡不进登录——MuMu 实测）；
* 账号名读官方 user_info（JWT claims 无名字字段）；
* 空设备列表 RangeError 崩溃修复；
* 监控引擎设备同步改为 UI 推送 + 30s 兜底轮询（跨隔离体不再依赖
  存储轮询）。
