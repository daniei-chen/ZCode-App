# v1.1.4 — 返回层级按真机反馈重定（双端区分）+ 返回卡顿修复

> 版本：`1.1.4+15`。基于 v1.1.3 的真机诊断包与用户实测反馈，对返回层级做了
> 三处修正：设置返回一次到位、平板单次返回、列表返回不再等待。

## 变更

**1. 设置页返回 → 设备列表页（一次到位）**

撤销 v1.1.3 的"设置返回 → 对话页"跳转（`ManagePage.onFullPageReturned`
整条接线拆除）。设置/诊断/扫码都是普通页面栈弹出：返回即回到进入前的
设备列表页。真机反馈：设置返回落在对话页不符合预期，应当直接回设备列表页。

**2. 平板：一次返回直接露出设备页**

平板（最短边 ≥600dp，`isTabletLayout`）上官方页面是"对话 + 列表同屏"，
页内没有返回可控件——系统返回**跳过页内脚本**直接露出设备页
（日志 `reason=tablet_single_back`）。真机实测：在平板上跑页内脚本会
误触对话区控件（诊断包 `reason=no_change`，表现为"点赞动了一下但没返回"，
要按两次才回设备页），此路彻底关闭。

**3. 手机：列表页返回不再卡 1 秒**

v1.1.3 为"秒开秒返"竞态加的 1.2s 候选重试窗口，副作用是稳定状态下
列表页每次返回都白等 1.2 秒（真机诊断包连续 `WV109/not_found` 实锤）。
现在窗口只在**页面刚加载 6 秒内**生效：刚打开对话立刻按返回仍有保护；
页面稳定后无候选时立即回执，返回瞬时到位。

**4. 导入设备后停留在设备列表页**

扫码/换链接导入完成后不再自动跳到远控页。此前直达远控页会把官方页面的
"正在配对工作区 / 加载工作区中"过渡页露出来（v1.1.2 及之前该页一直被
设备列表页覆盖，用户不可见）。恢复既有行为：导入完成后停在设备列表页，
由用户点开设备。

## 返回层级（现行口径）

| 场景 | 按返回后 |
| --- | --- |
| 设置 / 诊断 / 扫码（手机与平板） | 回到设备列表页（普通弹栈） |
| 对话页（手机） | 对话列表（页内返回，`WV112/clicked`） |
| 对话页（平板，与列表同屏） | 设备列表页（一次到位，页内脚本不跑） |
| 对话列表（手机） | 设备列表页（页面稳定后立即返回） |
| 设备列表页 | 退出应用 |

## 验证（本机模拟器：Android 15 / WebView 151 / 真实官方页面）

- 注入脚本校验器 **32/32**：新增"页面刚加载（<6s）无候选 → 仍走重试窗口"
  与"页面已稳定（>6s）无候选 → 立即 not_found 不安排任何定时器"两条行为断言。
- Dart 测试：返回层级组更新为新口径（设置返回停在设备页、平板判定
  `isTabletLayout` 边界 600dp），全套通过（CI 为准，Windows 本地仅 4 例
  已知引擎着色器限制失败）。
- 模拟器双端实测：手机（320×640）对话→列表→设备页→退出逐级验证；
  平板（800×1280dp，Pixel Tablet 规格 AVD）设置→返回→设备列表页、
  远控页→返回→一次露出设备列表页。
