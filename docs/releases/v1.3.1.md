# v1.3.1 — 通知断电根因修复：头无监控引擎 + V2 连接补 token

> 版本：`1.3.1+36`。针对用户实测反馈："有新消息还是没通知"。

## 根因（两个，都是硬伤）

**1. 通知管线随 Activity 一起被销毁（主根因）**

v1.2.x/v1.3.0 的通知逻辑全部活在**桌面 Activity 的 Flutter 引擎**里。
在最近任务里划掉应用、或系统/MIUI 回收 Activity 时，引擎随之销毁——
Dart 侧事件解析、通知决策全部停止。前台服务只保住了**进程**，保不住
引擎：进程活着，但没有任何东西在听事件、发通知。

修复：常驻服务现在**自持一个无 UI 的头无 Flutter 引擎**（入口
`monitorMain`），专跑原生监控通道与系统通知：

* 划掉应用 / Activity 被回收 → 头无引擎在服务里继续跑，照常提醒；
* 系统按 START_STICKY 重建服务 → 自动重新拉起引擎，监控自愈；
* UI 回到前台 → 头无引擎自动挂起（事件归 WebView 路径，避免双源重复）；
  离开前台 → 自动恢复，并重新读取设备表与登录令牌。

**2. v1.3.0 原生监控的连接地址是错的**

用真实链接从 PC 探针复现了服务端行为：缺凭证一律
`{"type":"error","code":"WRONG_PARAM"}` 拒绝。对照官方 3.16.3 页面
bundle 逐行确认，V2 终端连接的完整配方是：

```
wss://zcode.z.ai/ws?token=<账号JWT>&mid=<设备mid>
```

——**账号 JWT 必须放在 query 里**（`r.searchParams.set('token', …)`），
并非"裸 sid 即可"。v1.3.0 的监控从未真正连上过。

修复：监控连接按官方配方带 `token` + `mid`；JWT 由页面探针从
localStorage 捕获（打开一次远控页即完成，后续自动跟随登录态刷新），
存入安卓安全存储；锁定擦除时一并清除。没有令牌时绝不裸连，60 秒后
静默重试。

## 升级提示

* 装好后**打开一次任意设备的远控页**（让令牌捕获完成），之后回桌面 /
  锁屏测试：完成任务应有"完成通知"弹窗；关掉电脑约 1 分钟应有
  "连接已断开"静默通知。
* MIUI 的自启动 + 省电无限制仍然必须设置（设置页的保活引导会带你去）。

## 其他

* K1 边界修订：服务允许宿头无引擎，但原生侧仍然禁止任何直接联网——
  网络、事件解析、通知决策全部留在 Dart。
* 诊断锚点：监控配对成功会记 RL522 事件（真机排障从诊断包查它）。
