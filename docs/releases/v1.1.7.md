# v1.1.7 — 适配 ZCode 官方远控 V2 协议（账号登录 + 设备配对）

> 版本：`1.1.7+30`。ZCode 桌面端 3.16.3 改版了移动远控：二维码不再携带
> `hash`/`t`，配对凭证改为官方页的账号登录态 + 服务端设备注册。旧版 App
> 扫新码报「不是有效的远程控制二维码（缺少 sid/hash）」。本版逐项核对
> 桌面端与官方页实现后完成适配。

## 官方协议改版要点（2026-10 实测核对）

* **二维码格式**：桌面端 `buildWebRemoteControlExternalQrUrl` 现生成
  `https://zcode.z.ai/remote/v4?sid=<设备ID>&mid=<机器ID>&name=<主机名>&app_version=<版本>`，
  `hash`/`t` 已删除；`sid` 是注册在服务端的设备身份，不再是会话凭证。
* **配对流程**：手机页用账号登录态（JWT）连 `wss://…/api/v1/remote/ws2`，
  按 `sid` 找到同账号下注册的桌面设备完成配对；设备归属校验在服务端。
* **登录入口**：未登录时页面出现「连接 Z.ai（全球）/ 连接 BigModel（中国）」，
  主帧跳转 `chat.z.ai/api/oauth/authorize` 或 `bigmodel.cn/login`，
  完成后重定向回官方 origin。

## 变更

**1. 扫码/粘贴接受 V2 链接（核心修复）**

`LinkBuilder.parse` 凭证判定从「sid+hash 成对」放宽为「sid 或
remoteControlToken 其一非空」：V2 链接（只有 sid）可导入，V1 旧链接
（sid+hash+t）与最早的 token 链接继续可用。`buildUrl` 不再向 V2 链接注入
官方已删除的 `t` 参数（旧链接仍照旧刷新 `t`）。扫码失败文案同步改为
「缺少 sid」。

**2. App 内登录走得通（导航白名单扩展）**

原主帧白名单只放行 `zcode.z.ai/remote/vN`，登录跳转与 OAuth 回调会被静默
拦截。现放行官方 origin 任意路径（OAuth 回调、`/web-remote` 选电脑页）与
登录中转域 `chat.z.ai`、`bigmodel.cn`（含子域）。高权限 bridge 不随之下放：
仍由 `/remote/vN` 命名空间 + 主 frame 令牌单独把守。

**3. 登录态跨链接保留（Cookie 策略修订）**

换控制链接不再清空 Cookie（`preserveCookies: true`）——V2 的配对凭证就是
账号登录态，清掉等于每次重扫码都要重新登录。DOM storage 与 HTTP 缓存照旧
清理；锁定擦除仍全部清空（清 Cookie 语义不变）。

**4. 登录页/选电脑页不再被品牌盖板遮住**

盖板揭盖探针增加两个信号：主帧离开 `/remote/vN`（登录中转、选设备页）
立即揭盖；页面出现「登录后继续使用 / Web Remote Control Sign In」即视为
真实内容。用户首扫即可看到登录入口，不再对着品牌页等 12 秒超时。

## 兼容性

* 旧链接设备（sid+hash+t）无需重新导入，行为不变。
* 已在旧版导入的设备升级后继续可用；官方页 V1 `remoteControlToken` 流程
  未动。
* 升级路径：versionCode 30 > 已发布 29；应用内检查更新可直接升级。
