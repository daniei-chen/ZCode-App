# v1.8.5 — 修 agent 通道恒 down（审批通知从未建立）+ 去重窗口有界

> 版本：`1.8.5+53`。诊断包（v1.8.4）的关键信号：
> `306c9163.monitor = paired` 但 `dESHc6Ko.agent = down`，
> 同时 `wsMessages = 268` / `framesDecoded = 127` —— 数据一直在进来，
> 但**审批/输入事件的那条订阅链从未建立**。

## 根因一：workspace 键取错了层级

`activeWorkspaceKey` 在 **`payload.result` 里面**（
`docs/RELAY-PROTOCOL-VERIFIED.md` §3 的实测响应形状），而代码在 payload
**顶层**找它——永远取不到，于是桥开不起来。

```dart
// 旧
final key = result?['activeWorkspaceKey'];              // 永远 null
// 新
final key = result?['result']?['activeWorkspaceKey'] ?? result?['activeWorkspaceKey'];
```

## 根因二：开桥响应按错谓词匹配

同一份协议文档写得很明确：

> 匹配谓词按 `bridgeSessionId`，**不是** `requestId`（虽然本次实测
> `requestId` 也回了）

代码只按 `requestId` 匹配。一旦服务端按官方语义**只回
`bridgeSessionId`**，那个 completer 就永远等不到，桥开不起来。

现在两种谓词都接受（任一命中即算本次开桥）。

## 根因三：引导失败后永不重试

`onPaired()` 只在配对瞬间触发一次。引导链任何一步失败（网络抖动、
上面两个 bug 中的任何一个），agent 就一直 down 到**下一次重连**。

现在失败会指数退避重试（5s → 10s → 20s → 40s → 封顶 60s），
成功即清零。

## 顺带修：交互去重集合有界

`_seenInteractions` 原来是**无界** `Set`。头无引擎是常驻进程，长期运行会
一直涨；更实际的问题是永久去重会让"同一 interactionId 在重启后再次出现"
永远收不到提醒。改为保留最近 **512** 个（足够覆盖重放）。

## 验证

- 641 项测试全绿；
- **新增逐帧协议测试**（`test/agent_official_shapes_test.dart`）：
  完全按官方形状（`activeWorkspaceKey` 嵌在 `result`、`bridge-ready` 只回
  `bridgeSessionId`）驱动引导链，断言能走到下一步 hello；
- **新增重试测试**：故意不回响应，断言 20 秒内会再次发起引导；
- 已有的集成测试也改成官方形状（不再"迁就"旧实现）。

> 说明：本轮模拟器（MuMu）在重启后 adbd 一直 offline，**没能在设备上完成
> 端到端复跑**。这次修复的依据是官方协议文档 + 逐帧单测，而不是猜测；
> 装到真机后看诊断包的 `agent` 是否从 `down` 变 `true` 即可确认。

## 怎么确认修好了

装 v1.8.5，打开远程页用一会儿，然后导诊断包看这一行：

```
[monitor]
xxx.monitor = paired
xxx.agent = true          ← 关键是这个从 down 变 true
```

`agent = true` 意味着审批/输入事件的订阅链建立了——这是"审批通知"
能来的前提（完成/失败通知走的是另一条快照差分路径，本来就工作）。
