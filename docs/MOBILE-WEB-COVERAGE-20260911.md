# Mobile / Web 功能覆盖表（2026-09-11）

这份表是移动端验收边界，不把远控网页里的展示结果当作“已经接通”。
每个条目必须有真实 service RPC、可追踪错误态和对应测试，才算“已接入”。

## 原生功能与兼容总览

设置 → 功能与兼容提供 38 个桌面服务的原生总览，按“原生、只读、待接入、受限”筛选，
并显示每个服务的真实方法范围、当前限制和离线状态。它是能力边界页，不把待接入项伪装
成可用功能；已形成移动端入口的项目可继续进入对应原生面板。

底部导航只保留任务、面板、设备、设置四项。通知历史和审批仍在设置 → 收件箱，避免
把通知做成一个没有独立工作台的假导航页。

## 已接入读取，写操作必须继续显示真实限制

| 领域 | 读取接口 | 写接口 | 移动端现状 |
|---|---|---|---|
| 技能 | `skills.list` | `setEnabled`（用户/工作区） | 列表与用户/工作区启用已接入；插件/内置保持只读，删除和复制仍受限 |
| MCP | `mcp-sync.listLocalUserMcpCandidates`、`listRemoteUserMcpStatuses` | 导入/导出/同步 | 本地与远端状态可读，凭证脱敏 |
| 插件 | `plugins.getOverview`、`plugin-management.getPluginsOverview` | 安装、卸载、启用、市场管理 | 目录、市场摘要、插件 MCP 服务可读 |
| 子智能体 | `subagents.list` | 创建、更新、删除、启用 | 只读 |
| 钩子 | `hooks.loadHooks` | 保存、增删改、信任 | 只读 |
| 记忆 | `memory.listProjectMemories`、目录探测 | 保存、清空、读文件 | 目录/项目列表可读，正文不泄露 |
| 输出样式 | `output-style.listStyles` | 增删改、激活 | 只读 |
| 索引库 | `setting.get` | `setting.update` | 只读白名单 |

## 仍需协议或设备能力后才能接入

| Web 服务域 | 计划入口 | 当前原因 |
|---|---|---|
| `file`、`terminal`、`git` | 工作区/代码变更 | 需要明确的路径授权、写入确认和回执模型 |
| `browser` / `computer use` | 工具页 | 需要 CUA 权限和会话生命周期，不能用假浏览器替代 |
| `settings-sync`、`skill-sync`、`plugin-sync` | 同步/迁移 | 需要归档传输、冲突和覆盖确认 |
| `repo-wiki`、`feedback`、`bots` | 项目工具 | 需要补齐目标项目与写入协议 |
| `oauth`、`credential`、订阅/计费 | 账户设置 | 凭证和计费域禁止在移动端猜测或代操作 |

## 验收规则

1. 页面不能用 WebView 的被动文本拼接冒充原生数据。
2. 接口未返回、方法不存在、权限拒绝、空数据、旧数据必须分别呈现。
3. 写操作只在请求参数和成功回执都有证据时开放；失败时不能保留乐观成功状态。
4. 新增 service 必须同时增加 fake relay 契约测试和至少一个失败态测试。
