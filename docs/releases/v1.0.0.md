## 本版内容（相对上一交付版）

**1. 修复"正在加载工作区"卡片仍会露出（真机双端复现）**

上一版把隐藏器重写为 1 秒节拍扫描后，真机上卡片仍会显示。定位到根因：
扫描对**文本节点长度设了 120 字符上限**，而官方页把卡片正文（标题 + 说明 +
4 个步骤）渲染成**单个文本节点**（约 130–180 字符）——整段被跳过，永不隐藏。
（此前本地"仿制卡片"恰好约 75 字符，测试因此漏过。）

修复并加第二层保险：
- 文本节点上限 120 → **600**；
- 新增**屏幕九宫格命中测试**探测（`elementsFromPoint`）：卡片/覆盖层必然
  覆盖采样点，不依赖文本节点结构；
- 卡片判定仍要求命中 **≥2 个不同关键词**，避免误伤引用单个词的聊天正文。

验证（真实页面 + CDP，四种形态）：
| 形态 | 结果 |
| --- | --- |
| 短单文本节点卡片（约 75 字） | 已隐藏 |
| **超长单文本节点卡片（约 150 字，旧上限漏网场景）** | **已隐藏（修复生效）** |
| 多节点拆分卡片 | 已隐藏 |
| 聊天消息仅含一个关键词（防误伤） | 保持可见，不误伤 |

**2. 系统返回键：平板/大屏也走页内返回（口径修订）**

撤销"平板上跳过页内返回脚本"的规则：它导致 web 设置面板（如"插件"页）
按系统返回直接退出到设备页，与用户预期相反（用户要求：等同于点击页面
左上角的「返回工作区」）。现在手机与平板同一条路径：有页面自带返回控件
就点它；没有（对话+列表同屏页）则一次返回露出设备页。

**3. 安全门禁死锁修复（随本版一并发布）**

读取安全设置失败时锁屏提供「清除安全设置并继续」（二次确认）；若系统
存储损坏写不进，确认标记写入独立的安全存储后端，重启后不再锁死；
读取失败的异常记入日志（SL903）便于诊断；重新打开指纹锁会自动清除标记。

  - 修复前：`{"id":901,"ok":false,"reason":"not_found"}`，设置页仍打开。
  - 修复后：`{"id":900,"ok":true,"reason":"clicked"}`，设置页关闭。
- 负向过滤本身保留（几何 / 通用路径仍防误点），并补 2 条断言：aria-label 含
  "设置"的图标键仍必须跳过、testid 含 `settings` 的官方返回键必须被点掉。

**2. "还是有加载工作区 / 加载中还是能看到"——盖板揭开过早**

- 真机时序（文档级观察器，reload 后逐帧记录）：`+1.2s` 英文中转屏

## build 24（1.0.0+24）— 安全与一致性修复版

本版来自一轮独立安全审计（b3 审计包的 R-02～R-18 逐条核实与独立复现），
不新增用户可见功能；修复集中在"安全恢复语义、凭证状态一致性、发布门禁"三条线上。

## 安全恢复（锁屏恢复不再免验证）

- **锁屏恢复改二选一，删除"确认即关闭"路径**：设备系统存储异常、指纹锁读不到
  时，用户可以 ① 用系统锁屏凭据（PIN/图案/密码）验证身份后关闭故障开关（设备
  与链接都保留），或 ② 清除本机全部远控数据后免验证进入。不再存在"点两下就
  绕过身份验证"的路径。
- **持久化失败不放行**：安全设置写不进去（prefs 与独立安全存储都失败）时保持
  锁定并给出明确提示，不谎报"已关闭保护"。
- **恢复确认面板不再依赖 Navigator**：锁屏位于整棵路由树之外，旧实现用系统
  对话框会直接报错、按钮完全不可用；现在改用锁屏内联确认面板，生产拓扑下实测
  可用（此前该路径在真实构建里打不开）。

## 数据清除（"清了磁盘、内存还在"的半完成状态）

- **新增受保护状态擦除事务**：清除数据时同步清空设备列表、活动会话、会话索引、
  连接状态、事件、遥测、桥令牌健康、待跳转目标、预热脚本（含在途延时写入），
  再清磁盘、WebView 站点数据（localStorage/IndexedDB/Cookie/缓存）与系统通知。
  事务任一步失败即保持锁定并提示重试。
- **"读不到"不再被当成"没有设备"**：安全存储枚举失败时如实报告故障（可重试），
  且不会写入空索引（旧行为会把一次临时故障固化成永久丢设备）。
- **设备变更命令串行化**：并发的新增/重命名/换链接/删除/排序不再互相覆盖；
  删除后不会被在途的重命名把凭证写回。

## 更新器与发布门禁

- 检查更新：API 超时后的网页回退不再因客户端被提前关闭而失败。
- 摘要伴随文件（`.sha256`）请求同样走逐跳白名单校验，不再自动跟随重定向。
- 发布校验要求 sidecar 为 `sha256sum` 标准行格式（摘要 + 精确文件名），与应用
  内校验、命令行 `sha256sum -c` 三方一致。
- 依赖漏洞门禁：CVSS 向量（v2/v3）现在能正确换算严重度；无法判定的条目单独
  记为"未评估"并在发布时阻断（此前高危向量会被静默放行）。
- 插件存活门：绑定同一次构建的 APK、mapping 与发布清单（空产物/换 mapping 不再
  可能通过），并接入发布流水线必需步骤。

## 其它

- WebView 换链接后同步控制器原子重建：新凭证下的状态与事件不再被静默丢弃。
- 启动盖板 20 秒兜底改为独立计时器：页面探针持续失败时也会揭盖，不再出现
  "永远的品牌图标"。

## 已知边界

- 真机项目（生物识别/相机/通知/后台/长稳）仍需实体设备验收，本版未替代。
- 版本名保持 1.0.0：已安装 1.1.x 的设备在应用内不会把本版识别为"有更新"，
  覆盖面安装升级不受影响（内部版本号继续递增）。

## build 25（1.0.0+25）— b4 复审整改版

来源：桌面 b4 复审报告（7.2/10 候选版）。本轮整改三项 P1（本地可闭环部分）与一项 P2：

### 桥接消息预算（R-13）

- 超限判定改为**真实 UTF-8 字节**，并在 `JSON.parse` **之前**收口——超预算正文不再
  进入解析路径（此前中文/emoji 内容字符数低于上限、字节数却可超标约 3 倍）。
- 桥未就绪时的队列同时受**字节数与条数**约束，按 UTF-8 真实字节计账。
- 分片重组增加**全局在途总额**（16 MiB）与槽位上限——多个"各自合法"的未完成分片
  不再能把内存叠加到预算之外。
- `fragmentCount` / `fragmentIndex` 必须是有限整数（小数下标被拒绝并计数）；
  `messageBytes` 声明值不再被信任（按 base64 编码长度判定）。

### 擦除事务的失败语义（R-17）

- 擦除每一步现在都产出**逐项结果**；只有**全部必需项成功**才关闭门禁，任一项
  失败保持锁定并显示可重试提示（此前站点数据/通知失败会被静默放行，与文档不符）。
- 系统通知撤销的契约明确：成功只证明**撤销请求已提交**（插件没有查询通知栏的
  API），失败按未完成处理。

### 观察面（P2）

- SSE 不再被观察：协议实测记录（`docs/RELAY-PROTOCOL-VERIFIED.md`）捕获到的
  全部事件通道是 WS/REST，EventSource 从未出现、也不属于本应用事件通道；
  现完全不挂监听（只计 `sseIgnored`，便于诊断页发现未来变化），页面行为不受影响。

### 工具链一致性

- Flutter 版本统一为 **3.47.4**（与交付 APK 的 manifest.toolchain 一致）；CI、SUPPORT
  与构建说明同步；文档防漂移检查新增"Flutter 固定版本一致"（含漂移负例）。

### 验证（build 25 快照）

- `flutter analyze` 0；`flutter test` **574/574**；注入脚本门 **47/47**；
  四个发布脚本自测 20/22/25/9；文档防漂移 8/8。
- 用 b4 复审方的受控 VM 方法复跑修复后探针：**8/8**（越界输入不进入解析/桥/内存留存）。

## build 26（1.0.0+26）— b5 评审整改版

来源：交付前 code-reviewer 闸门对 build 25 整改批的独立评审（1 条阻断级 + 2 条高优 +
5 条中低）。build 25 未交付外部，本版直接取代之。

### 桥接预算记账修正（阻断级 + 高）

- **队列条数淘汰按字节扣账**（阻断级）：`qBytes -= q.shift().n` 误把 handler 名当
  字节数 → `qBytes` 变 `NaN`，字节上限静默失效（只剩 2048 条数上限）；改为条目
  自记字段 `.w`，并补"先塞满 2048 条再入队大消息"的 JS 门回归（回退修复即失败）。
- **重复分片差量回收**（高）：重复投递同一 `fragmentIndex` 时全局在途预算
  `asmBytes` 只加不减，可被永久耗尽、导致该会话分片观察整体停摆；补
  `asmBytes -= oldLen` 差量，并以"重复片后合法帧仍可解出"作行为回归。

### 擦除失败语义补充（高）

- **通知撤销加一次短退避重试**：插件通道瞬时故障不再把"擦除失败"永久化

### 记账语义

- `ObservedEvent.pendingTotal`：differ 在 request / resolved 事件上携带转移后的
  权威剩余量（permission + userInput）；任务整行消失（removed）为 null。
- `DeviceFeed.pendingByTask: Map<String,int>`（原 `Set<String>`）：请求事件有计数
  直接采信、无计数只保证在场；`resolved` 有正计数直接写入并保留红点，null/0 走旧的
  逐键清理（含 unknown 占位键回退）。**同任务审批+输入并存，解决一条不清红点。**
- 系统通知只在剩余 ≤ 0 时撤销（`webview_sync.dart`）。
- **缺 summary = 未知，不是 0**：`SessionState.hasPendingSummary` 三值语义。
  `controller/tasks-index` 的任务行天然不带 summary 且与镜像一起进 differ——同一投递
  内它不覆盖带 summary 的镜像，跨投递沿用基线计数（`inheritPendingFrom`），避免把 1
  覆盖成 0 产生假 resolved 误清红点。

### 复审加固（零上下文 code-reviewer + security-auditor 发现，同批修复）

  回绕误撤通知）；时间戳只认有限值；`ingestMessage` 外层兜底 try/catch 走 BR202 留痕。
