# v1.1.8 — 账号登录态全保留 + V2 协议失败通知

> 版本：`1.1.8+31`。基于 v1.1.7 真机反馈：重扫二维码后要重新登录；
> 任务失败时没有通知。

## 变更

**1. 账号登录态全保留（核心修复）**

实测官方页把账号鉴权存在 localStorage（`zcodejwttoken`、
`oauth:*:access_token`、`oauth:active_provider`）+ Cookie。v1.1.7 在换
链接时保留了 Cookie 但仍清空 localStorage，导致重扫二维码、桌面端升级
（QR 里 `name`/`app_version` 变化）后都要重新登录。

现在换控制链接**只清 HTTP 缓存**；账号登录态跨链接、跨重扫保留——登录
一次即可。「清除本机数据」（锁定擦除）不受影响，仍然全清（新增
`wipeAll`：Cookie + DOM storage + 缓存一次清空）。

**2. V2 协议失败通知（app-error 信封）**

桌面端 3.16.3 的失败信号是协议明面的 `app-error` /
`workspace-bridge-error` 信封。新增专用解析器只认 `zcode_type` 字面量，
直接映射为 error 通知；不并入裸 `type:'error'` 通道（旧页面流式期间的
嵌套 error 噪音仍归 StateDiffer 终态判断），避免过程噪音误报。

**3. V2 协议核验结论（v1.1.7 适配的实测补充）**

* 新页面 WebSocket 仍连 `wss://zcode.z.ai/ws`，App 的观察白名单命中；
* 注入钩子的信封解码（payload/frame/data 走查、base64 帧解码、分片重组）
  正是 V2 中继的帧形态，事件通路设计上完整；
* 任务行 DOM（`data-testid^="task-item-"`）未变，盖板/跳转锚点有效。

## 说明

* V2 是**账号 → 多设备**模型：登录态按账号共享，切换电脑可在页面内
  「切换设备」完成；App 的设备列表条目本质是"账号门户 + 指定设备"。
* 通知不弹的排查路径：系统设置里确认 App 通知权限 → 测试时把 App 切到
  后台（前台时只走应用内浮窗，是设计行为）→ 仍无效则导出诊断包
  （wsMessages/framesDecoded 计数可直接定位事件流是否存活）。

## 验证

* `flutter analyze` 零问题；全套测试无新增失败（4 个本机环境性失败与
  干净 main 一致，CI 为准）。
* 升级路径：versionCode 31 > 已发布 30，签名同钥匙（07091ffd…），
  覆盖安装免卸载。
