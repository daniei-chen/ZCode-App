# v1.7.0 — 接管死循环根治 + 账号头像实名 + 记录按 sid 收敛

> 版本：`1.7.0+44`。用户反馈"一直显示被其他设备接管，完全不能解决"。
> 本轮把官方中继的**单控制端语义**实测清楚（双终端探针 + 官方 bundle
> 文案双实锤），从三个方向根治互踢死循环，并补上账号行的头像与实名。

## 接管死循环：根因与修复

官方语义（3.16.3 bundle `session-conflict` 卡原文）：**同一设备同一时间只
允许一个手机控制端**。双终端实测：后连者立刻把先连者踢下线
（`{"type":"error","code":"KICKED"}` + close 1006）。

此前监控引擎被踢后 3s 就重连抢槽，与"正在用槽位的会话页 / 另一台手机 /
模拟器上的旧安装"反复互踢——会话页永远停在"已被其他设备接管"卡（官方页
该状态**没有自动重试**，只有手动"重新连接"按钮）。三面收口：

1. **监控被踢让路（RL523）**：收到 `KICKED` → 状态 `yielded`，退避改为
   20s 起指数封顶 120s，期间绝不抢槽；修复被踢 done 事件覆盖让路状态的
   竞态（传输代次守卫）。诊断页可见"让路"状态。
2. **前台/后台确定性交接**：后台冻结会话页 JS（`pauseTimers`）——官方页
   被踢后会自动重连抢槽，冻结后槽位干净地归监控引擎（通知不断）；前台
   归会话页（既有 suspend 机制）。
3. **前台自愈重连（WV115）**：回前台或错误出现时，页面若停在接管卡/
   错误态，静默重载一次收回槽位（15s 节流，防真故障刷页）。

## 同 sid 双记录收敛（DS704）

同一台电脑的两条设备记录（旧手动导入 + 账号自动导入）会在常驻
IndexedStack 里**同时开两个会话页**，两个终端按单控制端语义自相互踢——
症状与跨设备接管完全一致。现在存储加载时按 `device_sid` 收敛：保留
index 序最前者（用户原始命名/排序），重复记录删除。

## 账号行：头像 + 实名（v1.7.0）

- 探针升级：官方 `oauth:*:user_info`（含 `displayName` / `avatarUrl`，
  bundle 字段实证）登录完成即抓取，JWT claims 仅作名字兜底。
- **持久化**：重启后账号行仍是实名 + 头像，不再依赖"进过一次远控页"。
- **头像渲染**：白名单图床（z.ai / bigmodel.cn / zhipu* / chatglm.cn）
  的 https 头像直显；不在名单或加载失败回退字母头像（黑白原生风），
  原生侧不新增任意第三方网络面。

## 其他

- 监控状态机新增 `yielded`，连接状态聚合与诊断页同步可读。
- 手动设备的删除入口（长按菜单）保持不变；账号设备来自官方目录，
  服务端未对手机端开放注销路由，设备的增删以桌面端为准（登录账号
  变化会自动跟随目录）。
