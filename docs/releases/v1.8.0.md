# v1.8.0 — 外置通知通道：用桌面 hook 绕开单控制端约束

> 版本：`1.8.0+48`。用户提出"能不能加个插件让手机收到每条通知，像
> DeepSeek harness 那样外置"——这个方向是对的，而且是从架构上绕开
> ZCode relay 单控制端约束的唯一干净解法。

## 为什么之前一直在打架

ZCode 中继是**单控制端**语义：同一台电脑同时只允许一个手机终端。App 内
本来就有两个终端（会话页 / 后台监控），v1.4 起还有第三个（agent 命令
通道，v1.7.1 已并入监控）。它们的组合变换——尤其每次前后台切换——就是
"一直被其他设备接管"的根源。继续优化终端的交接只能减少冲突，无法消除。

## v1.8.0 的做法：换一条完全不同的路

**桌面端主动推**，手机只收，完全不碰 relay：

```
桌面 ZCode hook（PermissionRequest / Stop）
        │  POST（带令牌）
        ▼
   zcode-push 服务（用户自己的云服务器）
        │  长轮询
        ▼
   手机 App → 系统通知
```

### 服务器（`server/zcode-push/`）

- Python 标准库单文件 + SQLite，**零第三方依赖**；
- 自有 Docker 容器，与服务器上现有服务完全隔离（独立卷、只监听
  127.0.0.1、内存上限 256M、`no-new-privileges`）；
- 所有数据接口都要 `X-ZP-Token`（常量时间比较），令牌由
  `openssl rand` 生成、600 权限；
- 有界存储：投递确认即删，未投递保留 7 天 / 最多 2000 条；
- 日志只记方法与路径，**从不记录消息体或令牌**。

### 桌面安装（`install_zcode_hook.sh`）

一条命令注册两个 hook：

```bash
bash install_zcode_hook.sh --url https://<你的服务> --token <令牌>
```

- 令牌写入 `~/.config/zcode-push/token`（600），**不放进命令行参数**
  （避免进入 shell 历史与进程列表）；
- 上报脚本失败一律 `exit 0`——**通知发不出去绝不能阻塞 ZCode 的任务**；
- 自检：装完直接发一条测试消息；
- `--uninstall` 一键移除，也可用 `--dry-run` 先看要写什么。

### App

- 新增 `lib/services/external_push.dart`：协议层（可单测）+ 前台/后台
  两个轮询器；
- **游标在共享 prefs 里**：UI 引擎与头无引擎不会双响；
- 设置页新增「外置通知通道」：填地址 + 令牌，点「保存并测试」当场验证；
- 令牌存 secure storage（与 JWT 同级），地址存普通 prefs；
- 消息进同一个通知中心（用户只翻一处），点通知深链到会话。

## 与 relay 通道的关系

**两条通道独立并存**：

| | relay 监控 | 外置通道 |
|---|---|---|
| 来源 | ZCode 中继快照差分 | 桌面 hook 主动推送 |
| 占终端槽位 | 是 | **否** |
| 需要 App 在后台存活 | 是 | 是（但不需要抢槽位） |
| 审批按钮 | 有（agent 通道） | 无（只深链，避免再开终端） |
| 依赖 | 登录态 / 单控制端 | 桌面装 hook + 一个令牌 |

外置通道不取代 relay——它是"更稳的另一条路"。两条都工作时，refs 由
`EventDedupeGate` 按 (type, taskId, summary) 去重。

## 验证

- 服务器端到端实测：公网 HTTPS → nginx → 容器 → SQLite，
  401 鉴权、publish、poll、ack（投递后即删）全部通过；
- 626 测试全绿（新增 13 条协议单测：解析/游标/https 约束/去重）。

## 升级后怎么用

1. 装 v1.8.0；
2. 电脑上跑 `install_zcode_hook.sh`（地址填你自己的部署域名，
   令牌见服务器 `/etc/zcode-push/token`）；
3. 手机 App → 设置 → 外置通知通道 → 填同一组地址与令牌 → 「保存并测试」，
   当场应该收到一条测试通知；
4. 之后桌面端每次审批/任务结束都会自动推到手机。

> 服务器端已部署完成（容器 `zcode-push` 运行中，nginx 新增
> `location ^~ /zpush/`，回滚方式见 `server/zcode-push/README.md`）。
