## ZCode App v1.1.3

> 本版修复用户上报的**返回键失效**，并在真机诊断包与本机模拟器上完成了根因定位与
> 回归验证。默认仍是 **Pre-release**（应用内更新器只认 `/releases/latest`）。

### 修复

**1. 主 frame 桥令牌竞态（返回失效的直接原因）**

真机诊断包证据：

```
W BR200 event=bridgeTokenMissing dev=ca3a0d6d gen=0
W WV109 event=webviewBackFailed ... reason=unavailable  ×8（一分钟内每次返回）
```

`onLoadStop` 时 `window.__zrToken` 从未落地 → 页面钩子按 fail-closed 规则
（"没有令牌绝不裸发"）把事件、遥测、**返回回执**全部排队 → 返回键看起来"没反应"，
页面事件/通知在同一台设备上也会静默失效。

修法：令牌改由 **document-start UserScript 预置**（钩子安装时直接读），运行期注入
保留为备份并加 read-back 校验 + 退避重试；返回键前有 ≤1.4s 的"等令牌到位"预算。

**2. 返回键几何兜底误点（模拟器实测的第二个 bug）**

用 WebView DevTools 协议读取真实官方页面 DOM 后确认：返回键是
`button[aria-label="返回任务首页"]`，位于 `(8,10,24,24)`；而**任务列表页左上角
没有任何返回控件**，旧规则（左上 96px 内）会把工作区切换/新建等控件当成返回键
点掉 —— 表现为"越返回越往里走"。几何兜底已收紧为"左上 56×40 内、20–40px、
图标型（有 svg 或无文本）"。

**3. provider 写入时机（模拟器上直接崩溃）**

`initState` 期间上报桥健康状态会抛
"Tried to modify a provider while the widget tree was building"（红屏）；
改为帧后回调。

**4. 返回层级补齐（用户要求）**

- **设置页返回 → 远控页（对话/列表）**，不再停在设备页；之后逐级返回：
  对话页 → 对话列表 → 设备页 → 退出应用（手机与平板同一套规则）。
- 平板：对话页与对话列表同屏，页内没有可点控件时脚本如实报 `not_found`，
  由外壳直接露出设备页，不做多余点击。
- 页内返回脚本增加 **1.2s 候选重试窗口**：刚打开对话就立刻按返回时返回键可能
  还没挂上，旧实现直接判 `not_found` 会让返回键闪回设备页。

### 验证（本机模拟器：Android 15 / WebView 151 / 真实官方页面 + 真实桌面数据）

自动化循环（脚本在仓库外，逐轮用 CDP 读页面真实状态 + 结构化日志双重校验）：

| 步骤 | 期望 | 结果 |
| --- | --- | --- |
| 对话页 --返回--> | 任务列表 | `WV112 event=webviewBackHandled reason=clicked` + 页面状态 `list` |
| 列表 --返回--> | 设备页 | `WV109 reason=not_found`（页面确无返回控件，不误点） |
| 设备页 --返回--> | 退出应用 | 应用退出至系统桌面 |

**对话页 ↔ 对话列表 ↔ 设备页 ↔ 退出**：长跑 100 轮中除夹具噪声外全部通过
（85+ 轮完整通过；14 次失败经逐条核对属夹具——应用重启后 DevTools 目标未及时
重建、探针读不到页面，夹具已加重试，与应用行为无关），无误点、无红屏、
无令牌缺失告警。**设置 → 远控页**已用截图单独确认。
