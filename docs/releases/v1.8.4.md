# v1.8.4 — 收拾收尾 + 三处体验优化（通知不折腾了）

> 版本：`1.8.4+52`。用户决定不再投入外置通知通道（配置成本太高），
> 本版把这部分收进折叠项，把精力放回日常真正用得上的地方。

## 一、外置通道收进"进阶"折叠项

那套配置（自建服务 + 桌面 hook）对日常使用太重了，之前 377 行 UI 一直占着
通知设置首屏。现在默认收起为一行：

```
🔬 进阶：外置通知通道
   需要自己的服务器与桌面端配置          ▼
```

点开才是完整配置，收起后完全不干扰。**已有配置不受影响**（轮询器照常工作）。

## 二、体检新增"通知实际送达"检测

这是本轮最实用的一项。原来体检只查**权限是否开启**，但"权限开着"和
"真能收到通知"是两件事——渠道被关、免打扰、厂商拦截都会让通知静默消失。

现在体检会**真的发一条本地通知**，然后报告它是否成功：

| 项 | 含义 |
|---|---|
| 通知权限 | 系统是否允许本应用发通知 |
| **通知实际送达** | 真的弹了一条测试通知，你现在就该看到它 |

失败时点"修复"直达系统通知设置页逐项检查，不再只报一个红叉。

## 三、首页设备卡显示摘要新鲜度

以前只显示"运行中 / 已完成"，但你分不清那是 **10 秒前**还是 **3 小时前**
的状态（进程早停了，最后写下的摘要还留在那里）。现在带上相对时间：

```
运行中 · 重构认证模块 · 刚刚
已完成 · 修复登录闪退 · 2 小时前
```

分档：`刚刚`（<1 分钟）/ `N 分钟前` / `N 小时前` / `N 天前`。
缺 `updatedAt` 或时钟回拨时不显示（不制造噪声）。

## 验证

- 639 项测试全绿（新增 4 条新鲜度测试 + 1 条时钟边界）；
- MuMu 模拟器安装启动：进程存活、crash buffer 0 条；
- 全量 `flutter analyze` 零问题。

## 关于通知的现状（如实说明）

内置 relay 通知链路（v1.7.x 修的那套）仍然工作；外置通道作为进阶选项保留，
配置好后可用。**如果日常用内置通知仍不稳定，最实际的下一步不是继续改代码**，
而是在真机上跑一次体检看"通知实际送达"是否通过——那一项会直接告诉你
是权限/渠道问题，还是真的链路问题。
