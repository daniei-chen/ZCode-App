# v1.8.3 — 修复"保存并测试"假成功（拉到消息却不弹通知）

> 版本：`1.8.3+51`。**本轮在 MuMu 模拟器上做了真实端到端验证后才发布**
> （用户要求：确保完全成功再发）。

## 真 bug：假成功

`设置 → 外置通知通道 → 保存并测试` 的旧实现：

```dart
final batch = await fetchExternalPushOnce(config: config, after: 0, ...);
// 只读数量，从不调用 showExternalPush，也不推进游标
```

后果有两个：

1. **消息被静默消费**：从 `after=0` 拉走了队列里的消息，但**一条通知都没弹**。
   用户看到"通道可用"，实际什么都没收到——这正是"通知还是不行"的直因之一。
2. **游标没推进**：下次真轮询时服务端消息已被前面那次拉取"看过"，若此时
   再做 ack 就会永久丢消息。

## 修复

测试路径改为**真的投递**：

- 用**共享游标**拉取（不再从 0 开始）；
- 每条消息都调用 `NotifierService.showExternalPush()` 弹系统通知；
- **只 ack 真正弹成功的那批**（发失败的留给轮询器重试，绝不"服务端删了但没弹"）；
- 结果文案如实反映：`已保存并弹出 N 条通知（队列原有 M 条）`。

## 模拟器实测记录（MuMu / Android 15）

完整链路四轮验证：

| 轮次 | 场景 | 结果 |
|---|---|---|
| 1 | 前台 + 点"保存并测试" | 队列 `pending 1→0`，通知 `id=1394031741`、`groupKey=zr_push`、`importance=4`、`actions=1` |
| 2 | **切后台（Home 键）** | 队列 `pending 1→0`，新通知 `id=1515302536` 正常弹出 |
| 3 | 后台连续两条 | 两条都被取走，通知各一条 |
| 4 | 全程 | 进程 pid 不变，crash buffer **0 条** |

关键证据（`dumpsys notification`）：

```
NotificationRecord(id=1394031741, importance=4,
  channel=zr_conn_v8_sound, groupKey=zr_push,
  flags=AUTO_CANCEL, actions=1, vis=PUBLIC)
```

`groupKey=zr_push` + `actions=1` 是 `showExternalPush()` 的独有特征，
证明这条通知确实由外置通道发出，而不是其他来源。

## 回归防护

新增 3 条单测锁住游标语义：

- 从非零游标拉取只返回更新的消息；
- 空批次不推进游标（`nextCursor` 为 null），有消息时必须严格大于 `after`；
- **ack 只包含真正投递成功的 id**（发失败的不 ack）。

## 仍需你手工完成的一步

App 端与服务器之间**已经完整验证通过**。但桌面端那半条链路需要你在
ZCode 里手工配置 hooks（ZCode 不允许命令行写 hooks 文件）：

```
设置 → 钩子 → 新建
  事件 PermissionRequest   命令 bash ~/.config/zcode-push/notify.sh PermissionRequest
  事件 Stop                命令 bash ~/.config/zcode-push/notify.sh Stop
```

保存时若提示需要信任，**必须点允许**。在此之前，桌面端不会自动推送；
你可以先用上面的方式直接往服务器 POST 验证手机侧（本版已实测可用）。
