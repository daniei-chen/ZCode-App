# v1.1.7 — 握手卡真正冷处理 / 设置返回按页面实际布局 / 主题按钮同步 / 文案

> 版本：`1.1.7+18`。基于 v1.1.6 真机反馈（含实拍截图），修四处问题。

## 变更

**1. "正在加载工作区"卡片终于被稳定冷处理（本地注入实验定位）**

用真机同样的卡片在页面上做注入实验：卡片注入 3 秒后仍可见——证明隐藏器
早已停止工作。根因有两层：① 观察器有 60 秒 deadline，到点即死，之后出现
的卡片（切换会话、重连）再也没人处理；② "命中即断开"让重建的卡片漏网。
重写为**长生命周期扫描**：1 秒节拍、30 分钟上限、文本节点级定位
（TreeWalker，单次预算 ≤4000 个文本节点），冷启动前 90 秒叠加 mutation
触发；卡片判定要求命中 **≥2 个不同关键词**，避免聊天正文引用单个词时
误伤消息气泡。

**2. 设置返回的落地按**页面实际布局**判断（不再靠屏幕尺寸猜）**

真机两次误判（600dp 阈值把大屏手机判成平板、700dp 又把小尺寸平板判成
手机）后改为探测官方页自身：**任务列表行与输入区同时存在 = 对话/列表
同屏**。进入设置前通过远控页控制器探测当前设备的真实布局，同屏 → 设置
返回揭示同屏页（再返回才到设备页）；否则 → 返回停在设备列表页。探测
失败时才回退到尺寸启发式。

**3. 主题按钮与实际主题同步**

问题：在设备管理页把主题切成夜间，官方页配色变暗，但它自己的"主题选择
按钮"还写着日间（React 状态只在挂载时读一次，就地改类名不会更新它）。
修复：**页面被设备页遮盖时**切换主题改为整页重载（用户看不见，重新挂载
后按钮与实际主题一致）；页面可见时仍走即时 DOM 应用。

**4. 文案**

- 设置页"生物识别门禁" → **指纹锁**
- 删除其副标题"开启或关闭都需要先通过系统验证"
- "改善后台运行稳定性" → **电池限制**
