# v1.7.1 — 接管死循环终局：app 内单终端化（agent 并入监控连接）

> 版本：`1.7.1+45`。v1.7.0 发布后用户反馈"还是在被接管"，诊断包
> （`monitor=paired` + `agent=down` 轮流出现、前台 suspend 失效）定位出
> 互踢的最后两个来源——都在 app **内部**。

## 根因一：agent 命令通道是第二条常驻终端（v1.4 起的真正源头）

`RelayAgentNotifier` 为每设备自持一条常驻 WS（审批按钮的事件源）。官方
中继是"单控制端"语义（同 device_sid 只允许一个终端）——它和监控连接
互踢，也把用户正在看的会话页一起踢成"已被其他设备接管"。v1.4-v1.6.2
监控引擎从未启动（入口缺失），所以只有"agent vs 会话页"在踢——**接管
问题从 v1.4 就开始了**；v1.6.3 修好监控后又加入第三个竞争者。

**修复**：`RelayAgentLayer` 并入监控连接——配对成功后在**同一条 socket**
上走 workspace-list → 开桥 → hello/initialize → 订阅链。app 内每设备
永远只有一个终端：前台=会话页、后台=监控（自带 agent 能力）。命令提交
同 socket；通知动作分发器（独立 isolate）保留一次性连接兜底。

## 根因二：前台 suspend 被 30s 重载撤销

`RelayMonitorNotifier.suspend()` 只删连接，30 秒周期重载随即原样建回——
前台监控"诈尸"，把用户会话页踢下线。修复：让路标志挡住所有重建入口
（周期重载/设备推送/设备表变更），直到 resume。

## 验证

- 新增集成测试：单 socket 走完 agent 引导链并就绪、命令同 socket 提交、
  被踢后 agent 复位、未启用层行为与旧版一致（608 测试全绿）。
- 诊断口径不变：体检"命令通道"= 监控连接上的 agent 层就绪态
  （`writeAgentReady` 键兼容）。

## 升级注意

**所有安装过本 app 的设备都要升到 v1.7.1**（包括模拟器/旧测试机）——
任何一台留在旧版本的设备都会成为"其他设备"抢槽位。v1.7.1 的让路退避
（20s 起）把跨设备冲突从死循环降级为偶发礼让，但升级才是根治。
